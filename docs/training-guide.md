# Training Guide

## Purpose

This guide defines the minimum training package for frontline users, clinician reviewers, supervisors, and programme leads before a controlled MindMap Care pilot.

Training must reinforce that MindMap Care is screening and triage support only. It is not diagnostic and does not replace clinical judgment.

## Training Audiences

| Audience | Training focus |
| --- | --- |
| Screeners | consent, intake quality, screening completion, privacy on shared devices |
| Clinician reviewers | risk summary interpretation, explanation caveats, override, referral, escalation |
| Supervisors | queue monitoring, missing data, follow-up gaps, user support, incident reporting |
| Programme leads | aggregate monitoring, pilot metrics, workflow fit, go/no-go decisions |
| Technical support | deployment status, user access, logs, downtime, rollback, incident support |

## Core Modules

### 1. Safe-Use Orientation

- intended use and limits
- non-diagnostic positioning
- human review requirement
- risk categories and recommended actions
- what to do when system output conflicts with human judgment

### 2. Consent And Privacy

- approved consent language
- when not to proceed with screening
- minimum necessary data
- shared-device precautions
- handling printed or exported reports
- reporting privacy concerns

### 3. Screening Workflow

- start a screening
- capture required fields
- handle missing or uncertain responses
- submit a record
- recognize validation errors
- explain the tool to a client without overstating it

### 4. Risk Summary Review

- read risk category, explanation factors, caveats, and model limitations
- identify missing-data warnings
- apply local triage pathway
- record review outcome
- document override reason
- refer or escalate according to local procedures

### 5. Queue And Follow-Up Management

- monitor pending reviews
- identify high-risk and urgent cases
- update referral status
- update follow-up status
- prioritize unresolved high-risk cases
- escalate overdue actions

### 6. Incidents And Downtime

- recognize safety, privacy, technical, and workflow incidents
- use manual downtime procedure
- report access or export concerns
- know who can pause pilot use
- document issue timeline and follow-up

## Quick Reference

| Situation | User action |
| --- | --- |
| Client does not consent | Stop digital screening and follow local care pathway |
| Required field is missing | Resolve before submission where possible or flag for review |
| Low-risk output but clinical concern exists | Use clinical judgment and escalate manually |
| Moderate or high output | Route to clinician review and record action |
| Urgent or crisis concern | Follow local urgent escalation pathway immediately |
| System unavailable | Use approved paper or manual workflow and log downtime |
| Privacy concern | Stop exposed workflow, notify supervisor, document incident |

## Training Completion Evidence

Before pilot launch, record:

- training date
- trainer
- participant name and role
- modules completed
- practice case completed
- open questions
- sign-off status

## Practice Cases

Training should include at least:

- one low-risk synthetic case
- one moderate-risk synthetic case
- one high-risk synthetic case
- one urgent or safety-flagged synthetic case
- one missing-data case
- one override case

## Refresher Cadence

- before pilot launch
- after major workflow or scoring-rule changes
- after safety or privacy incidents
- when new users join
- at least monthly during the first pilot
